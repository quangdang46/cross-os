fix: Reset Everything reported success and reset nothing

Run for the first time, on a daemon with a plugin on, one shortcut
bound, one window zone defined and onboarding complete. It said every step
was done:

    OK  stop intercepting        tap stopped and the kill switch latched
    OK  remove login item        not installed
    OK  delete the settings file …/CrossOS/config.json
    OK  forget ownership records records cleared

and `plugin.list` still answered with `windows-keyboard` enabled and
healthy, `config.getShortcuts` with all ten, and `config.getZones` with
its zone. **Two reasons, and both were mine.**

**Deleting the file does not reset a running daemon.** The store holds the
running state in memory and writes the document on every change, so
removing the file underneath it leaves the process serving exactly what
it still had. The file was gone and the settings were not, which is worse
than either. `Store.Clear` returns the process to the state a fresh
install loads, through the same write path every other mutation uses, so
the file and the process agree afterwards — the property this package
argues for in every other comment.

**Forgetting that a plugin was enabled is not the same as stopping it.**
The enable set and the running catalog are separate facts, and a reset
that only forgets leaves the plugin intercepting keys after the page says
everything is off. Reset now disables what is running first, and names
what it stopped in its report.

Measured after the fix, on the same configuration:

    OK  stop intercepting
    OK  remove login item
    OK  stop the plugins running   windows-keyboard
    OK  clear the settings         shortcuts, zones, overrides, disabled
                                         rules, enabled plugins, profile and
                                         onboarding cleared
    OK  delete the settings file
    OK  forget ownership records
    NOT verify no CrossOS process remains   pending — a process cannot
                                            verify its own absence

    enabled plugins []  shortcuts 0  zones 0  onboarding False  file gone

Five of six done and the sixth reported rather than claimed, which is the
right shape for the most destructive control in the app.

I wrote this control and had never run it. The click test presses Reset
Everything's button and asserts the guard, but nothing was checking what
the method does once the confirmation is answered.
