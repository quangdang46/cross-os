docs: the checks now run against both a cold and a configured daemon

The previous commit fixed a defect that only appeared on a COLD daemon,
and every green result in this repo's history had come from a warm one.
The other direction had never been measured at all: **nothing had ever
run the audit or the click test against a daemon a person had actually
configured**, which is the state every real user is in.

So the daemon here now has a plugin switched on, a shortcut bound, a
window zone defined and one matrix rule disabled — the state a user
reaches after ten minutes with the app.

Both checks, in both appearances:

    --audit            15 pages, 0 fail, 0 unmeasurable   (light)
    --audit --dark     15 pages, 0 fail, 0 unmeasurable   (dark)
    --click-test       PASS

And the click test is **idempotent against real state**, which is a
stronger claim than passing against an empty one. It read the plugin as
enabled, toggled it off, and put it back:

    plugin switch   stored true -> false

Verified after the run, reading the daemon directly:

    plugins after : [('windows-keyboard', True), ('developer', False), …]
    rules after   : [False, True, True]
    profiles after: [('windows-11-experience', False)]
    status after  : killed False

Every value it touched is back where it started. That matters because
the test is a CI gate that presses PANIC STOP and Reset Everything, and
a gate that leaves a machine changed is a gate nobody will run twice.
